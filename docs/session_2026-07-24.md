## ⚠️ The one decision that constrains everything downstream

**282 of 300 gold labels were produced by an LLM annotator, 18 by a human.**

Consequences, already written into `docs/er_metrics.md` and `docs/labeling_guide.md`:

- The headline metric measures **agreement between the local pipeline and an LLM annotator**,
  not accuracy against human ground truth. Say so wherever it is quoted.
- **2.6's Claude adjudicator cannot be scored against these labels** — that is self-consistency,
  not correctness. Evaluate it on the 18 human rows only, or do not claim adjudicator accuracy.
- recall@k on the LLM subset is **biased upward** (the annotator saw candidates before deciding).

Reassuring but not conclusive: the human subset scores *higher* (94.1% @50) than the LLM subset
(90.3%). Rubber-stamping would have put the LLM subset near 100%. n=17 — a smoke test.

**Cheapest available fix (~15 min of human time):** blind-relabel ~30 random strings without
seeing existing labels → converts the caveat into a measured agreement rate. Mode not built yet.
85 labels are flagged `confidence: low` and are the best targets for review.

## What was built (9 commits, `e00580c` → `65f6bdb`)

### 2.0 — Bronze hardening (`e00580c`)
Tests written first; 4 failed against the old code.
- **0-row `overwrite` wiped a table** → now raises before any write (real defect)
- **Uncapped `Retry-After`** → `min(…, 60)`; `999999` had meant an ~11-day stall (real defect)
- **Non-list 200 body** → raises instead of iterating dict keys (real defect)
- Retry/backoff and idempotency were *correct but untested* — now covered. Idempotency tests
  re-run with **different** input so a stale no-op cannot pass.
- `iceberg_scan` f-string → bound parameter.

### 2.1 — Ingredient line parsing (`7ec91fd`)
`bronze.raw_recipes` → `silver.recipe_ingredient_lines` (112,463) +
`silver.distinct_ingredient_strings` (**9,324** distinct — a ~12× collapse).
93.7% of lines carry a quantity (independently reproduces the 93.8% Phase-1 sample figure).

Three defects found only by running against the real corpus:
- comma cut erased ingredients when the prefix was all filler (`drained, crushed pineapple` → `""`)
- the `" or "` cut had the identical failure mode
- a chained second unit survived (`6 oz. can lemon juice` → `can lemon juice`), fragmenting the
  ER set so `tsp salt` resolved separately from `salt` — 658 distinct strings affected

### 2.2 — USDA normalization (`3e9ed64`)
`silver.usda_foods`, 8,187 entities. Energy keyed on nutrient **number**, not name:
- `Energy` appears under **two units** — 7,887 foods carry both `208 [KCAL]` and `268 [kJ]`.
  Name matching would have produced values 4.184× too large on 96% of the corpus.
- 73 foods have no energy at all → **kcal coverage is 99.1%**, not the ~100% previously assumed.
- `foodCategory` is absent from **0/8,187** payloads; the leading comma facet is the proxy.
- Deprioritization flagged 58 staples (apples, beans) because the FDC boilerplate contains a
  caps token; only that one phrase is stripped — every other parenthetical is a real synonym
  (`(scallion)`, `(kiwi)`, `(pinto)`, `(calamari)`).

### 2.3a — Labeling guide + frozen sample (`28a7f45`)
Convention written **before** labeling. Split assigned at sampling time so it cannot be
influenced by the labels. Gold labels are now version-controlled (`.gitignore` negation) —
they are irreplaceable judgment, not regenerable data.

### 2.4 — Candidate generation (`caab28d`, corrected in `65f6bdb`)
731,527 rows, ~78 candidates/string, full run in **36s**.
Notable: **single-word generic queries retrieve worse than specific ones** — `cheddar cheese`
hits at cosine 1.000 while `flour` ranks its correct entry 57th, because USDA's canonical entry
is often a 5-facet string. That tension is what 2.5's specificity feature must close.

### 2.3b — Labeling CLI (`19d04a4`, `1fb373f`, `2ff0fb1`)
Search escape hatch (without it recall@k would be 100% by construction), split never displayed,
sample verified against manifest + Silver before labeling.
Then made tractable: base-form display ordering, fuzzy search (`token_set_ratio`, chosen by
comparing all five scorers on realistic typos), 5-row shortlist with ENTER-to-accept.
- **Facet count is a bad proxy for canonical** — the ordinary entry often has *more* qualifiers
  (`Egg, whole, raw, fresh`) than a rare variant (`Egg, white, dried`). Ranking by first-facet
  match + plain modifiers works; counting facets does not.
- Bug fixed: with nothing relevant, the plain-modifier bonus headed `dream whip` with
  Arrowhead/Taro/Pummelo. Bonuses now require lexical relevance.

### Gold set + metrics (`65f6bdb`)
**recall@50 = 90.5%** (@5 68.6, @25 84.8, @100 92.0). Null class 36/300 (12.0%).

**Measurement bug found and fixed:** candidates recorded one `method` — whichever generator
found them *first* — so `embed_search` claimed nearly every row and the A/B was unmeasurable
(`embed_desc` 1.1%, `token_head` 0.4%). Now three independent membership booleans:

| Generator alone | recall@50 |
|---|---|
| `embed_search` (reversed facets) | 90.5% |
| `embed_desc` (raw description) | 88.6% |
| `token_head` | 40.2% |

→ **Reversing the facets is worth ~2pp**, not the large gain assumed when both forms were built.

By stratum: head 93.5%, **mid 86.4% (worst)**, tail 91.7%. The tail is mostly brands and parser
artifacts that are cleanly `no-match` and excluded; mid holds real-but-awkward foods.
