## 2. Phase 4, as built

```
4.0  silver.recipe_meta        titles — Gold could not name a recipe
4.1  agent/retrieval.py        SQL over the export; word-boundary matching, measured
4.2  agent/context.py          the contract between retrieval and the guardrail

4.7  agent/planner.py          constraint solving in code; the model narrates
4.8  agent/explain.py          runbook entries for failures, guardrailed like an answer
4.9  er/dietary.py             per-entity dietary classification  [after the review]
```

**Design decisions inside the code**, each with a wrong-but-plausible alternative:

- **Division is not a permitted derivation.** A recipe carries `servings: 8` and
  `kcal_per_serving: unknown` at once; 3,470/8 = 433.75 is exactly what §3.4 refused to publish.
- **Sums are not permitted either** — measured first, not assumed: the false-positive rate without
  them is 0%, so they were never bought.
- **Verified totals need their own channel.** Forbidding sums made the planner refuse to describe
  its own week plan. `AnswerContext.computed` carries figures the *planner* computed and checked.
- **`unknown` is a real answer** in the dietary classifier, and disqualifies exactly like `no`.
  705 of 8,187 entities come back unknown.
- **List markers are positional, not vocabulary.** A unit denylist let through "It serves 2",
  "Makes 2 portions", "$2 total" — the same anti-pattern the dietary tags were condemned for.

## 3. The review — five reviewers, and two false headlines

Fanned out across measurement, code correctness, test quality, LLM/injection, and data.

**Headline 1: the guardrail's 100% catch rate was a tautology.** The harness discarded an
injection when `permitted()` accepted it, then counted it caught when `check()` — the same
predicate — rejected it. 90/90 agreement, zero independent information. An adversary built to
always defeat the guardrail scored 100% through it. Honest figure: **40%**.

**Headline 2: the dietary tag numbers came from a regex not in the repo.** Published "13 → 5 /
9 → 4" were title-leak counts under a pattern nothing pinned. By entity inspection the rule left
**30/572 vegetarian (5.2%) and 16/134 vegan (11.9%)** falsely tagged. Two recipes tagged *vegan*
were a ribs recipe and a cocktail-wieners recipe.

Other confirmed findings: `explain.Finding.prompt()` did no escaping at all and is the only
untrusted path with no model in front of it; `guarded_answer` returned the fallback paired with
the *rejected retry's* verdict, corrupting the log's own catch-rate metric; `EXACT_BELOW = 20`
rejected 51% of rounded sub-20g macro quotations; the safety assertions ran outside the gate and
could block nothing.

## 4. Mistakes I made, and how they were caught

| mistake | how it surfaced |
|---|---|
| Published a catch rate that could only ever print 100% | a reviewer checked whether the statistic could report anything else |
| Published false-tag counts from a regex that exists nowhere in the repo | a reviewer tried to reproduce them and got 8 → 1 |
| Told the user the quality explainer was not in Phase 4's DoD | it is — design doc §124. The error is why they deferred it |
| Wrote a `has_gluten_line` check using `SIMILAR TO '%(...)%'` | DuckDB's `SIMILAR TO` treats `%` as a literal; it matched nothing. Caught by running it |
| Measured tag leakage with a directions signal that matched 0 of 15,000 | ran the control: `directions` is a JSON *string*, and joining it as a list spaced out every character |
| Hand-wrote a regression set for the dietary classifier | **the classifier corrected 4 of 30, all in the unsafe direction** — Worcestershire is not gluten-free (malt vinegar) |
| Applied the `)\w*\b` suffix to the gluten veto and not the meat veto | a reviewer tested inflected forms: `hamburger`, `sausages`, `steaks` all missed |
| Claimed 19 mutation survivors were closed | replayed them — 4 still survived, all gaps in tests I had written |
| Wrote four tests that named a property they could not fail on | a mutation sweep, which brought the project's running total to eight |

The pattern is the same every time and it is the useful lesson: **a claim written next to real
work reads as though it has been checked.** Every one of these was caught by measuring the claim
separately, and none by re-reading it.

### Open, and recorded rather than dropped

- **Entity resolution at 67.3% is the ceiling under everything.** The dietary tags need three
  extra filters precisely because the classifier judges an entity that may be the wrong one.
- **The corpus ships truncated ingredient lists.** `coverage = 1.0` cannot see a missing line.
- **Small integers are dense in the allowed set** — 38% of injected numbers collide with a real
  value, which is why whole-dollar costs and reworded serving counts are the guardrail's weakest
  classes.
- **Four mutation survivors remain** and are not defects: two provably equivalent, one equivalent
  for any realistic input, one targeted the dead code now removed.
